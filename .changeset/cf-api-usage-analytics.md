`client.usage` reads each product's usage hour by hour from Cloudflare's GraphQL Analytics API, for a list of resource ids and a time range, and returns one row per metric, resource and UTC hour (`{ dataset, metric, resourceId, hour, value }`, `hour` in Unix seconds). It covers Workers by script name (requests, subrequests, errors, CPU time), Durable Objects by namespace id (invocations, active time, GB-seconds of duration, SQLite rows read and written, WebSocket messages, key-value storage units, SQLite storage), the busiest single Durable Object's alarms per namespace and hour, D1 (rows read and written, database size), KV (reads, writes, deletes, lists, stored bytes), R2 by bucket (one metric per operation, so class A and class B can be told apart, and stored bytes), Queues (billable operations), Workflows (instance starts, steps, CPU time), Workers AI by model (neurons, requests), Vectorize (queries, queried and stored dimensions), Analytics Engine (data points per dataset), Browser Rendering by script (sessions and browser time) and Containers by application (allocated memory and disk in byte-seconds, CPU seconds, bytes sent). Every request carries the current time in its filter, because Cloudflare otherwise answers the same query from a cache for 20 minutes or more. Ids are sent in batches, ranges in windows of at most 30 days, and a full answer is split again until it fits. GraphQL errors, which Cloudflare sends with HTTP 200, throw `CloudflareGraphQLError` with Cloudflare's messages and codes.

New calls to pause and resume an app's parts: `workers.getScriptSettings` and `workers.setObservability` (`/workers/scripts/{name}/script-settings`: turns Workers Logs on or off without a new version, and changes no other setting), `containers.setMaxInstances`, `queues.getQueue` and `queues.setDeliveryPaused`, and `workflows.listInstances` (every page, optionally by status), `workflows.pauseInstance` and `workflows.resumeInstance`.

Every manager sign-in now also asks for `account-analytics.read`. `missingSpendProtectionScopes` says whether a grant lacks it, the one scope usage reads with, so a manager connected before can ask for a reconnect.
